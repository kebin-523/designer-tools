# 컬러 팔레트 기획서 (v0.4)

> `[확정]` 사용자가 직접 정한 내용 / `[가정]` 제가 기본값으로 채운 내용 (수정하고 싶은 항목만 알려주세요)
> 공통 UI(색, 글자, 버튼, 카드, 탭 등)는 **전체 디자인 가이드(design-system.md)** 를 따릅니다. 이 문서에는 컬러 팔레트만의 내용을 적습니다.

---

## 1. 한 줄 요약

기준 색 하나를 고르면 **보색·유사색·단색 명암·삼각 배색** 네 가지 조합을 한 화면에 보여주고, 색 이름과 글자·배경 대비를 확인한 뒤 마음에 드는 팔레트를 저장해 두는 페이지. `[확정]`

## 2. 문제와 목표

**문제**
- 메인 컬러는 정했는데, 어울리는 보조색과 강조색을 고르는 데 시간이 오래 걸린다. `[가정]`
- 고른 색이 글자와 배경으로 쓰기에 충분히 잘 읽히는지는 따로 도구를 열어 확인해야 한다. `[가정]`

**목표**
- 색 하나만 넣으면 조합 후보 네 종류가 한 번에 나온다.
- 색 값을 한 번의 클릭으로 복사해서 디자인 툴에 바로 붙여 넣는다.
- 글자와 배경으로 쓸 두 색이 읽기 좋은지 바로 확인한다.

## 3. 대상 사용자와 사용 상황

| 항목 | 내용 |
|---|---|
| 주 사용자 | 디자이너 (폰트저울, 무드보드와 동일) `[가정]` |
| 사용 상황 | 메인 컬러를 기준으로 보조색·강조색 후보를 찾고, 화면에서 쓸 수 있는 색인지 확인할 때 `[가정]` |
| 사용 환경 | 데스크톱 브라우저 우선, 모바일은 보기 가능 수준 `[가정: 디자인 가이드와 동일]` |

**대표 시나리오**
1. 명상 앱의 메인 컬러를 정했다. 색상 피커에서 비슷한 색을 고르거나, 이미 정해진 HEX 코드를 입력한다.
2. 네 가지 조합이 한 화면에 나온다. 앱 화면에 쓰기엔 유사색이 안정적이고, 강조 버튼에는 보색이 좋아 보인다.
3. 보색 조합에서 강조색을 골라 글자·배경 대비를 확인한다. 부족하면 같은 색의 밝기 변화(단색 명암)에서 더 어두운 색으로 바꾼다.
4. 색 값을 클릭해 복사하고 디자인 툴에 붙여 넣는다.
5. 마음에 드는 팔레트는 저장해 두고, 다음 작업 때 다시 불러온다.

## 4. 1차 버전(MVP) 범위

### 포함 `[확정]`

| 기능 | 설명 | 사용 예 |
|---|---|---|
| 기준 색 정하기 | 색상 피커로 고르거나 HEX 코드를 직접 입력 (둘 다 지원) | 브랜드 가이드의 코드를 그대로 입력 |
| 4가지 조합 보기 | 보색, 유사색, 단색 명암, 삼각 배색을 한 화면에 표시 | 조합별로 나란히 보며 분위기 비교 |
| 색 이름 표시 | 각 색 칩 아래에 색 이름 표시 | 팀원에게 "이 청록색"이 아니라 이름으로 설명 |
| 색 값 복사 | 색 칩의 HEX 값을 클릭하면 복사 | 디자인 툴에 바로 붙여 넣기 |
| 글자·배경 대비 확인 | 글자색과 배경색 두 개를 골라 대비 비율과 통과 여부를 표시 | 버튼 글자가 충분히 읽히는지 확인 |
| 팔레트 저장·불러오기 | 마음에 드는 팔레트를 저장하고 목록에서 다시 불러오기 | 지난 프로젝트의 팔레트를 다시 참고 |
| 연결 실패 시 대체 계산 | 색 조합 서비스에 연결하지 못하면 화면 안에서 직접 계산해서 같은 4가지 조합을 보여준다 | 서비스가 멈춰 있어도 작업이 끊기지 않음 |

### 제외 (2차 이후 검토)

- 무드보드 사진에서 색을 뽑아 기준 색으로 보내기 `[가정]` (실현 가능한지 아직 확인하지 않음)
- 팔레트를 폰트저울 비교 카드의 글자색·배경색에 적용하기 `[가정]`
- 팔레트를 이미지나 코드(CSS 변수)로 내보내기 `[가정]`
- 색 이름의 한글 번역 `[가정]`
- 로그인, 공유 링크 `[가정]`

## 5. 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│  로고/이름                 폰트저울  무드보드  [컬러 팔레트] │
├──────────────────────────────────────────────────────────┤
│  기준 색  [■ 피커]  [ #2563EB      ]                      │
├──────────────────────────────────────────────────────────┤
│  유사색                                           ☆ 저장 │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐                     │
│  │ ■  │ │ ■  │ │ ■  │ │ ■  │ │ ■  │                     │
│  │#... │ │#... │ │#... │ │#... │ │#... │  ← HEX 클릭=복사 │
│  │이름  │ │이름  │ │이름  │ │이름  │ │이름  │                     │
│  └────┘ └────┘ └────┘ └────┘ └────┘                     │
│  보색 / 단색 명암 / 삼각 배색  (같은 형태로 반복)             │
├──────────────────────────────────────────────────────────┤
│  글자·배경 대비 확인                                       │
│  글자색 [■ #111111]  배경색 [■ #FFFFFF]   대비 18.88 : 1  통과 │
├──────────────────────────────────────────────────────────┤
│  저장한 팔레트: [팔레트 1] [팔레트 2] …                     │
└──────────────────────────────────────────────────────────┘
```

- 조합 네 가지를 **세로로 한 줄씩** 쌓아 보여주고, 각 줄이 색 칩 여러 개로 구성된다. `[가정]`
- 조합 순서: 유사색 → 보색 → 단색 명암 → 삼각 배색. 안정적인 조합부터 보여주는 순서다. `[가정]`
- 색 칩, 카드, 별 버튼, 입력창은 디자인 가이드의 공통 컴포넌트를 쓴다.
- **포인트색 사용처**: 선택된 탭, 저장된 별 두 종류만 쓴다. 색 칩은 콘텐츠이므로 UI의 포인트색 개수에 넣지 않는다. 디자인 가이드의 "요소 종류 3가지 이하" 규칙을 지킨다. `[가정]`

## 6. 기능 상세

### 6-1. 기준 색 정하기 `[확정: 피커와 HEX 입력 둘 다]`
- 색상 피커와 HEX 입력창이 항상 같은 값을 보여준다. 한쪽을 바꾸면 다른 쪽도 바로 바뀐다. `[가정]`
- HEX 입력은 `#` 유무와 관계없이 6자리 코드를 받는다. 3자리 줄임 코드(예: `#F80`)도 받을지는 `[가정]` 받는 것으로 한다. 잘못된 값이면 입력창 아래에 "올바른 색 코드가 아니에요"를 보여주고 이전 색을 유지한다.
- 처음 열었을 때의 기본 기준 색은 디자인 가이드의 포인트색(`#2563EB`)으로 한다. `[가정]` (빈 화면을 피하고 바로 결과를 보여주기 위함)
- **색을 고르는 도중에는 호출하지 않고, 선택을 마쳤을 때만 새 조합을 불러온다.** 피커를 끌어서 움직이는 동안 호출이 계속 나가는 것을 막기 위함이다. `[가정]`

### 6-2. 네 가지 조합 `[확정: 4종 모두]`

| 화면 이름 | 의미 | The Color API의 모드 이름 |
|---|---|---|
| 유사색 | 기준 색과 이웃한 색 | `analogic` |
| 보색 | 기준 색과 마주 보는 색 | `complement` |
| 단색 명암 | 같은 색의 밝기 변화 | `monochrome` |
| 삼각 배색 | 색상환에서 세 방향으로 벌린 색 | `triad` |

- 각 조합은 기본 **5개 색**을 보여준다. `[가정]`
- 보색 모드가 색 개수를 늘렸을 때 어떤 색들을 돌려주는지는 **아직 직접 호출해 확인하지 않았습니다.** 만들기 전에 실제 결과를 보고 개수를 조정합니다.
- 조합 이름 옆에 한 줄 설명을 작게 붙인다. (예: "보색: 강조 버튼처럼 눈에 띄어야 할 곳에") `[가정]`

### 6-3. 색 이름 표시 `[확정]`
- 각 색 칩 아래에 색 이름을 작은 글자(`--text-caption`)로 보여준다.
- 이름이 어떤 언어로 오는지, 조합 결과 안에 이름이 함께 들어 있는지는 **확인이 필요합니다.** 이름이 따로 오지 않으면 색마다 추가로 호출해야 해서 호출 횟수가 크게 늘어납니다. (한 번에 약 20개)
- 이름을 불러오는 동안은 이름 자리에 자리 표시 박스를 둔다. `[가정]`
- 대체 계산 결과(6-7)에서는 색 이름을 제공하지 못하고 HEX 값만 보여준다. 이름 표시는 서비스에 연결될 때만 동작한다. `[가정]`

### 6-4. 색 값 복사 `[확정]`
- 색 칩의 HEX 값을 누르면 값이 복사되고, 그 자리에 "복사됨"이 1.5초간 보인다. `[가정]`
- 복사된 값은 `#2563EB` 형태(`#` 포함, 대문자)로 한다. `[가정]`
- 색 칩 자체를 눌러도 같은 동작을 한다. `[가정]`

### 6-5. 글자·배경 대비 확인 `[확정]`
- 글자색과 배경색을 각각 고른다. 두 색은 **현재 화면의 색 칩에서 선택하거나, HEX로 직접 입력**할 수 있다. `[가정]`
- 두 색의 **대비 비율(예: 5.17 : 1)** 을 보여주고, 아래 기준으로 통과 여부를 표시한다. `[가정]`

| 구분 | 기준 |
|---|---|
| 일반 글자 | 4.5 : 1 이상 |
| 큰 글자 | 3 : 1 이상 |

- 통과 여부는 색만이 아니라 "통과", "미달" 글자로도 표시한다. (디자인 가이드의 접근성 기본선)
- 대비 계산은 **화면 안에서 직접 계산**하는 것으로 가정한다. 외부 서비스를 호출하지 않으므로 호출 한도와 상관없이 항상 동작한다. `[가정]`
- 두 색으로 만든 **글자 미리보기**(짧은 샘플 문장 하나)를 함께 보여준다. `[가정]`
- 대비 비율 계산식과 기준은 널리 쓰이는 웹 접근성 기준을 따른다. 디자인 가이드의 색 대비 수치도 같은 방식으로 계산한 값이다.

### 6-6. 팔레트 저장·불러오기 `[확정]`
- 각 조합 줄의 ☆ 버튼으로 **그 줄의 팔레트(기준 색, 조합 종류, 색 목록)** 를 저장한다. `[가정: 저장 단위가 조합 한 줄]`
- 저장한 팔레트는 아래 목록에 색 칩 모음으로 보이고, 눌러서 **다시 불러오면** 그 팔레트의 기준 색과 조합이 화면에 복원된다. `[가정]`
- 기본 이름은 "기준 색 이름 + 조합 종류"로 붙이고, 이름을 직접 바꿀 수 있다. `[가정]`
- 저장할 수 있는 개수는 **20개**로 제한한다. `[가정]` (임시 값)
- 삭제는 목록의 삭제 버튼으로 하고, 확인 창은 두지 않는다. 저장은 쉽게 다시 할 수 있기 때문이다. `[가정]`
- 저장은 **브라우저 안**에 한다. 같은 브라우저와 기기에서만 유지되고, 브라우저의 사이트 데이터를 지우면 사라진다. 이 점을 목록 위에 한 줄로 안내한다. `[가정]`
- 저장할 때 색 목록 자체를 함께 저장하므로, 저장된 팔레트를 불러올 때는 외부 서비스를 다시 호출하지 않는다. `[가정]`
- 대체 계산(6-7)으로 만든 팔레트를 저장하면 목록에 "직접 계산" 표시를 함께 붙인다. 서비스 결과와 색이 다를 수 있다는 점을 나중에도 알 수 있게 하기 위함이다. `[가정]`

### 6-7. 연결 실패 시 대체 계산 `[확정: 대체 방식으로 진행]`

**언제 쓰나**
- The Color API 호출이 실패하거나(연결 오류, 사용 한도 초과), 정해진 시간 안에 응답이 오지 않으면 자동으로 대체 계산으로 넘어간다. 기다리는 시간은 **5초**로 가정한다. `[가정]`
- **평소에는 항상 The Color API 결과를 먼저 쓰고**, 대체 계산은 서비스에 연결되지 않을 때만 쓴다. `[가정]`

**어떻게 계산하나** `[가정: 구체적인 값은 만들면서 조정]`
- 기준 색을 색상(어떤 색인지), 채도(얼마나 선명한지), 명도(얼마나 밝은지)로 나눈다. 여기서 색상을 돌리거나 명도를 바꿔서 조합을 만든다.

| 조합 | 계산 방식 (임시 값) |
|---|---|
| 보색 | 색상을 180도 돌린 색 |
| 삼각 배색 | 색상을 120도, 240도 돌린 색 |
| 유사색 | 색상을 양쪽으로 30도 간격씩 돌린 색 |
| 단색 명암 | 같은 색상에서 명도만 단계별로 바꾼 색 |

- 각 조합은 서비스 결과와 같게 **기준 색을 포함해 5개 색**을 보여주는 것을 목표로 한다. 보색처럼 색이 두 개뿐인 조합에서 나머지를 어떻게 채울지는 만들면서 정한다. `[가정]`
- 이 계산식은 The Color API가 쓰는 계산 방식과 **같다고 확인한 것이 아닙니다.** 같은 기준 색이라도 서비스 결과와 색이 조금 다를 수 있습니다.

**화면에서 어떻게 보이나**
- 대체 계산 결과 위에 안내 띠를 보여준다. 문구 예: "색 조합 서비스에 연결하지 못해 직접 계산한 결과예요. 서비스 결과와 조금 다를 수 있어요." `[가정]`
- 안내 띠에 **다시 시도** 버튼을 둔다. 눌러서 연결되면 서비스 결과로 바뀌고 안내 띠는 사라진다. `[가정]`
- 대체 결과에서는 색 이름이 없으므로 HEX 값만 표시한다. (6-3 참고)
- 색 복사, 대비 확인, 저장은 대체 결과에서도 그대로 동작한다. 이 기능들은 외부 서비스에 의존하지 않기 때문이다.

## 7. 기술 방향

| 항목 | 내용 |
|---|---|
| 색 데이터 | The Color API `[확정: 앞서 합의한 조합]` |
| 제작 방식 | HTML 파일로 제작, 서비스별로 파일 분리, 세 서비스를 탭으로 전환 `[확정]` / 게시할 때의 파일 구성은 아직 미정 |
| 저장소 | 브라우저 내 저장 `[가정]` |
| 대비 계산 | 화면 안에서 직접 계산 `[가정]` |
| 연결 실패 대비 | 조합 4종을 화면 안에서 직접 계산하는 대체 방식 `[확정]` |

**The Color API에서 확인된 내용**
- 공식 문서에 조합 모드로 `monochrome`, `analogic`, `complement`, `triad` 등이 있고, 기준 색과 조합 개수를 지정해서 부를 수 있다. 위 4가지 조합은 모두 이 모드로 대응된다.
- 키 없이 쓸 수 있는 무료 서비스라는 설명이 있다. **API 키 노출 문제가 없다**는 점이 폰트저울(Google Fonts)이나 무드보드(Pexels)와 다르다.
- 무료 커뮤니티 서비스라 **가동 보장이 없고**, 같은 요청을 반복해서 보내지 않도록 결과를 재사용하라는 설명이 있다.

**미리 확인할 점**
1. **사용 한도**: 한도(시간당 호출 수 등)가 있는지는 확인하지 못했습니다. 기준 색을 자주 바꾸면 호출이 늘어나므로, **같은 기준 색의 결과는 화면에서 재사용**하는 것을 기본으로 합니다. `[가정]`
2. **서비스가 멈췄을 때**: 가동이 보장되지 않는 서비스라서, 호출이 실패하면 6-7의 대체 계산으로 넘어갑니다. 이때 결과가 서비스와 다를 수 있다는 점을 화면에 알립니다.
3. **브라우저에서 직접 호출 가능 여부**: 브라우저에서 바로 부를 수 있게 열려 있다는 소개는 있었지만 외부 소개 글 기준이라, 게시 환경에서 실제로 되는지는 직접 시험해야 합니다.
4. **게시 환경의 외부 접속 허용**: 게시하는 곳에서 The Color API 주소로의 접속이 허용되는지 확인이 필요합니다.

## 8. 성공 기준 (가볍게)

- 처음 방문한 디자이너가 설명 없이 1분 안에 기준 색을 정하고, 네 가지 조합을 보고, 색 값을 복사할 수 있다.
- 글자·배경 대비 확인에서 디자인 가이드의 색(예: `#111111` 위 `#FFFFFF`)을 넣으면 18.88 : 1로 나온다. (이미 계산해 둔 값으로 확인 가능)
- 저장한 팔레트가 새로고침하거나 다른 탭에 다녀와도 남아 있다.
- 외부 서비스 호출이 실패해도 화면 전체가 멈추지 않고, 5초 안에 대체 계산 결과와 안내 띠(다시 시도 버튼 포함)가 나온다.

## 9. 열려 있는 질문

1. **팔레트 저장 단위**: 조합 한 줄(색 5개)을 저장할지, 기준 색 하나에 딸린 네 조합 전체를 한 번에 저장할지
2. **색 이름의 언어**: API가 주는 이름을 그대로 쓸지, 한글 번역은 2차로 미룰지 (확인 후 결정)
3. **다른 탭과의 연동**: 팔레트를 폰트저울이나 무드보드와 연결하는 기능을 2차에서 다룰지
4. **대체 계산의 세부 값**: 유사색 간격(30도)과 보색 조합의 나머지 색 구성 (만들면서 결과를 보고 결정)

> 해결됨: 서비스 호출이 실패하면 화면 안에서 직접 계산하는 대체 방식으로 간다. (6-7 반영)
